# 設計

実装の構成は [`ARCHITECTURE.md`](ARCHITECTURE.md)、manor との連携は [`MANOR.md`](MANOR.md) に
分けてあります。ここには**何を作ろうとしているか**と、実機で確かめて決めたことを置きます。

## 1. 目的

作ろうとしているのは「XR レシピアプリ」ではなく、**キッチンに常駐する料理アシスタント**です。
柱は3本あり、どれも欠けると別のものになります。

| 柱 | 何 | 設計上の意味 |
|---|---|---|
| **A. 空間に定着した UI** | 毎回の起動で同じ場所に同じ板が戻る | アンカーは後付けの機能ではなく**土台**。毎日使うための条件 |
| **B. 独自テンプレートのレシピ** | 文字は極力少なく、画像を適切に。「今と次」と進捗% | レシピは**サーバ側で一度構造化**し、クライアントは表示に徹する。契約 JSON が最も長生きする成果物 |
| **C. ながら見の娯楽** | 料理中にショーツやドラマを流す | 動画は**レシピと無関係**な独立した板。レシピを動画で見るのとは別の要求 |

カメラ認識・自動進行は後段に置き、まずは固定の板を触って手動で進めます。ただし後段が入っても
壊れないよう、**認識器と進行器の分離**と**進行の状態機械**だけは最初から形を持たせます
（`CookSession.Apply(SessionEvent)`。認識は工程を進めず、観測を送るだけ）。

## 2. 設計原則

1. **料理中の手は UI 操作の意図ではない。** ピンチ＝クリックの単純設計にしない。手の姿勢を
   合図にすると、料理中の手は必ずどこかで合図を出す。
2. **文字入力を板に置かない。** ヘッドセットでの文字入力は使いにくい。入力が要ることは
   すべて manor の Web 側か、番号を出して Web で受ける形に寄せる。
3. **文字は最小に。** 短さは表示の都合ではなく内容の要件なので、**サーバで保証する**
   （`title` ≤ 12・`instruction` ≤ 60）。クライアントで切り詰めない。
4. **オフライン優先。** 台所では通信が切れる。表示は常に端末内の写しから行い、サーバへの報せは
   待ち行列に積むだけにする。**送れないことで調理は止まらない。**
5. **manor は XR に依存しない。** 依存は KitchenXR → manor の一方向で、XR 専用の口は作らない。
   レシピ帳と動画リストは manor 側の Web 機能であり、XR はその口を読む側に徹する。
6. **行き止まりを作らない。** 抜ける手段が1つしか無い状態（操作の板が挿さっていない・手が
   追えていない）では、そのモードへ入らない。
7. **機種依存は薄く。** XR SDK 固有の呼び出しは `Platform/<系>/` に閉じ、試験で検算する。

## 3. 見た目の決め

- **換算**: ワールド空間パネルは Pixels Per Unit 100・板の `localScale` 0.2 なので
  **1 UI px = 2mm**（20px = 4cm・10px = 2cm）。以下の数値はすべてこの換算です。
- **ボタン**: 最小 **20px（4cm）角**・間隔 **10px（2cm）**。押せるのは「次へ／戻る／タイマー／
  材料チェック」など数種だけで、大きく疎に置きます。
- **文字は3段**: 見出し 10px（≒48pt）・本文 6px（≒27pt）・補助 5px（≒24pt）。材料の行だけ
  さらに一段小さい 5.5px。1m 先で読める大きさを基準にしています。
- **配色**: 白 85% の半透明の板（`rgba(255,255,255,0.85)`）に濃灰の文字（`#1F2937`）。
  強調色は琥珀 1 色（`#F59E0B`）。角丸は大きめ・影は薄く。Unity 既定の見た目は使いません
  （`theme.uss` を全パネルが継ぎます）。
- **置き場**: 板は手の高さより上（胸〜目線）を既定にし、作業中の手が通る高さに置きません。
- **取り消し**: 常に1タップ（「戻る」）。取り消せない操作（一覧へ戻る・配置モードへ入る）だけ
  2度押しにします。長押しは使いません——手応えの無い板は深く入って留まるのが普通で、
  長押しと1回押しが区別できません。

## 4. 決定の記録

実機で確かめて直したことを、問題・決定・理由の1行ずつに圧縮したものです（v1.0.x）。
数字と識別子の裏は [`ARCHITECTURE.md`](ARCHITECTURE.md) にあります。

| 問題 | 決定 | 理由 |
|---|---|---|
| 文字が1つも描かれない | `theme.uss` を TextCore の FontAsset に結び、USS の長さに `px` を付けた | UI Toolkit は `TMP_FontAsset` を受け付けず指定ごと捨てる。単位無しの値は `var()` 越しで無視され 14px に戻る |
| パススルーが映らない | テンプレートの `Environment` ルート（床と空）を消した | チュートリアル UI のトグルが消す作りだったので、UI を外したら残り続けた |
| 触ると光るのにボタンが反応しない | 押し下げ（`PointerDown`）で発火し、押し上げは見ない | 調理中の手は深く入るので、押し上げが板の中で起きず `clicked` が出ない |
| 深く突き抜けると指が抜ける | 当たり判定の箱を**裏側にだけ** 24cm 伸ばした | 表の面＝押し込みの判定位置は板のまま。手前へ張り出すと触れる前に反応する |
| 板の左半分が押せない | `UIDocument.pivot` を `TopLeft` にした | 既定の `Center` では板の矩形とコライダーが半分ずれる |
| 二重に発火する | 600ms の間引きと「その指が板から離れるまで次を受けない」 | 留めたままでも2回目が起きないようにする |
| 文字より余白が大きい | 既定テーマの Label／Button の余白を落とし、間隔は要る場所だけ明示 | Unity 既定は 1 UI px = 1 画面 px 向けの値で、1 px = 2mm の板では過大 |
| 工程の板が1画面に収まらない | 頭を点列と進捗%だけ（8px）にし、本文を左右2列（左に正方形の工程画像） | 工程画像は契約上 1:1 で、縦に積むと幅いっぱいに伸びて説明を押し出す |
| 進捗が粗い | 点を**工程の数だけ**出し、phase の区切りは間隔と色で示す | 「次へ」で1つ進むことが見える |
| 材料が一目で全部見えない | 行の高さを 8px・行間 0 にし、板を 170×240 px に広げた | 押す釦の「最小 4cm 角」は材料の行には当てない——押し損ねても調理は進まず、一目で見えるほうが効く |
| レシピ一覧が読みにくい | 3列のカード（写真・題名・分／分類／kcal） | 写真の高さは「6 件までは縦スクロール無し」を優先して決めた |
| 板と文字の大きさが合わない | 一覧の板の中に設定の区画を置き、押した瞬間に反映して保存 | 板を増やすと置き場所を覚える対象も増える。「決定」は置かない |
| 電子レンジで通信が切れる | レシピ・画像は取得時に端末へ保存し、表示は常にローカルから。進行は待ち行列へ | 送れないことで調理を止めない |
| 配置の操作板が他の板と重なって押せない | 操作を全部手首のメニューへ移した | 手首のメニューは重なる相手が居ない。出口が1つになるので、挿さっていなければ配置モードへ入らない |
| 重なった2枚のどちらが掴めるか運任せ | 見えている板を取っ手役に選び、同じ鍵の残りは引っ込める | 起動直後に見えているのは一覧の板で、掴む仕掛けはレシピの板に付いていた |
| 壁の奥へ行った板が掴めない | 「板を手元に」で全部を初期配置へ並べ直す（配置モードは続く） | 「元に戻す」で入る前へ戻せるので1度押しでよい |
| 調理中にレイでボタンが押せてしまう | Interaction Layer（`Video`）と物理層 8 番の2段で絞る | Interaction Layer は UI Toolkit の当たりには効かない。`Ignore Raycast` ではポークの UI まで死ぬ |
| 手のひらメニューが手を洗っている最中にも出る | 手首の手のひら側に 4.4cm 角の釦を付けっぱなしにし、トグルで出す | 手の姿勢を合図にしている限り、料理中の手は必ず合図を出す。閾値を詰めても解決しない |
| レイの線が常に出ている | ホバー・選択のある間だけ描き手と `LineRenderer` を on/off | XRI に「無効なときは隠す」設定が無く、component を無効にすると最後の線が残る |
| 次の動画を選ぶ手段がない | 動画の窓への触りを通し、埋め込みプレイヤー自身の関連動画で選ぶ | 板に一覧を持たせずに済み、文字入力を置かない原則と噛み合う |
| 関連動画のタップが効かない | タップとドラッグを板の側で見分ける（絵の幅の 3%・1.2 秒） | 手の震えで必ず DRAG が挟まり、WebView がスクロールと解釈してクリックを出さない |
| 関連動画が `youtube.com` へ遷移すると操作できない | URL を監視して video_id を抜き、埋め込みプレイヤーへ連れ戻す | 遷移先では html の JS が丸ごと消える |
| ホログラムに手応えが無い | 発火の音を1つと、板の 5cm 以内だけに出る指先の光る点（近いほど大きい） | 常に出すと料理中の手にいつも点が付いて回る |
| 動画の一覧を `adb` で入れ替えるのが不便 | 一覧の正を manor へ移し、XR は写して読む | 編集は Web。同梱の `media.json` は manor 未設定のときの見本に格下げ |
| 合言葉を平文でファイルに置きたくない | 端末ごとの鍵（ペアリング）。番号は端末に出して Web で許可する | 板に文字入力を置かない以上、向きはこちらしかない |
| PC の LAN の住所が変わると繋がらない | UDP 8791 の探索を足し、見つけた口を控えに覚える | URL を固定で書くのは脆い |
| 横に置いた板へ手のレイが向かない | **直していない。** far 側の caster の安定化を 20° → 8° に緩めただけ | 手のレイの向きはシステムが作る体基準の照準姿勢で、設定では変えられない。出どころを差し替えるとレイの手触りが全部変わる |
| コンロの領域を Scene から取れない（意味ラベルにコンロが無い） | レイで**上面の高さに水平な作業面を仮に張り**、ピンチしたまま水平にドラッグして囲む | コンロは壁際で手が届かないので面をなぞらせられない。無限平面との交点は1行の数学で、AR の平面検出に頼らない |
| 注意の板に「消す」を載せると掴めなくなる | 「消す」を板の**兄弟**の小さな板にし、配置モードの間だけ出す | 配置モードの板は掴む相手（`XRGrabInteractable`）なので、同じコライダーに押せる釦を載せると引き当てが奪い合う。子にすると `UIDocument` が自分の板を作らず親の中の要素になる |
| 手元のメニューにプリセットの一覧が入らない | メニューを**頁**にして、頁ごとに板の高さを変える（動画の板の 16:9 ⇄ 9:16 と同じ仕掛け） | 板を増やすと置き場所を覚える対象が増える。手のひらの板は重なる相手が居ないので、伸ばすほうが素直 |

## 5. 越えられない線引き

- **DRM 付きの配信は WebView で再生できない**（Widevine L1 が無い）。YouTube・ショーツ・
  一般の Web 動画は出ます。これはプラットフォームの制約で、設計では越えられません。
- **LAN 上の HTTP は平文**（[`MANOR.md`](MANOR.md) §2）。Wi-Fi の無線区間は暗号化されているので
  家の中では受け入れていますが、残課題です。
- **手のレイの照準は体に紐づく**（§4 の最後の行）。真横に置いた板を指すには体を向けるか、
  板を 30〜45° 内向きに置く必要があります。
